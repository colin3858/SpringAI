## 关于 API 的错误排查

#### #### 接口调用返回 403 是什么原因？

**答：**
 403 表示“禁止访问”，通常有以下原因：

- 用户没有权限访问该资源
- 认证信息（Token）无效或已过期
- 访问路径被服务端拒绝

应检查权限配置或认证信息。

------

#### #### 为什么我发送了请求但收不到响应？

**答：**
 可能原因：

- URL 或端口错误
- 服务未启动或网络中断
- 请求被防火墙或代理拦截
- 请求参数导致服务端崩溃（查看服务端日志）

建议使用 Postman 或 curl 手动测试并查看后端日志。

------

#### #### 出现 500 错误应该怎么排查？

**答：**
 500 表示服务端内部错误。开发者应：

1. 查看服务端日志中的异常栈信息
2. 检查接口实现是否有空指针、数据库错误等
3. 检查请求数据是否非法导致服务端无法处理

------

#### #### 如何定位是前端问题还是后端问题？

**答：**
 建议按以下步骤定位：

- 使用 curl/Postman 复现请求，确认是接口问题
- 查看前端控制台和网络面板
- 检查接口是否存在并返回正确数据
- 比较请求参数与接口文档是否一致

------

#### #### 为什么我的参数看起来没问题，接口还是报错？

**答：**
 可能是：

- 参数类型错误，例如传了字符串但接口期望整数
- 漏传了某些必填字段
- 字段名拼写错误
- JSON 格式错误（如逗号、引号）

建议使用 JSON 校验工具检查参数格式，并比对接口规范。
